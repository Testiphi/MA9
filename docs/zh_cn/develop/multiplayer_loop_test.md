# 多人循环试跑

系列赛首页识别兼容白银/黄金两份样例：使用底部排行榜、里程碑、奖励文字及白色按钮亮度，入口再确认开始文字。不会用随段位变色的“经典系列赛”标题或评级文字。主页点击经典系列赛后的入口判断也使用同一组固定条件。

选车列表使用选车标题、收藏按钮及仅拥有开关识别，不匹配整排段位图标；当前段位与高亮样式变化不会阻断入口、推荐搜索或倒序兜底。白银起点新增实际 MuMu 截图用于回归，同时覆盖黄金滑动后的列表。

如果“仅拥有”首次点击被过场动画吞掉，循环会再次确认开关状态，仍关闭时最多重试至总共 3 次。选车详情页的“开始”也会在页面仍显示且 TouchDrive 已开启时最多点击 3 次，每次间隔至少 1.5 秒。次数耗尽后会停止，不会无限点击。MFA 显示“任务完成”也可能是 `StopTask` 触发，须检查 `install/debug/maafw.log` 中最后一个节点及 `install/debug/on_error/` 截图。

命令行实机入口 `tools/run_live_task.py 多人循环3局_入口 --timeout 900` 额外打印 `passed`、`rounds_completed` 和 `rounds_expected`。只有所有局数真正经过“本局完成”才是 `passed: true`；框架原始的 `succeeded` 不能单独用作判据。运行时列表 OCR 持续读不清会停止，现场截图写入 `debug/selection_ocr_failure.png`。首次黄金反查已验证 Praga Bohema 品牌误读恢复，并在第 10 页定位到 Panamera。

任务列表新增“识别当前选车或车辆详情状态（只读）”。停在选车列表或车辆详情页时单独运行，它只截图并报告 `selection_owned_on`、`selection_owned_off`、`detail_ready` 或 `unknown`，不点击游戏。报告写入 `install/debug/selection_diagnostic.json`；在开发环境从仓库根目录启动时写入 `debug/selection_diagnostic.json`。添加类似识别任务时，在 `assets/resource/pipeline/` 定义识别节点，以 `assets/interface.json` 的 `task` 项暴露入口；需要一次性汇总多个识别结果时可在 `agent/runtime_action.py` 添加 Custom Action，通过 `context.run_recognition` 复用现有节点。

刷新 Maa Pipeline Support，运行“多人循环试跑（白金/黄金/白银自动识别，连续3局，自动开赛）”。当前游戏实际段位应为白金、黄金或白银，语言为中文；可以从主页多人标签、系列赛介绍页、选车或车辆详情启动，也可从局内或结算接续。系列赛首页主体先于玩家段位徽章出现时，最多等待 9 秒并重复确认徽章，再判断是否属于不支持段位。白金分支已通过离线检查，仍需实机连续对局验证；3 局稳定后运行同名 20 局版本。

正式推荐来源为用户审核通过的 `各级别霸主.docx` 及 `champion_overrides.json`，数据快照为 `data/generated/champion_rotation.json`。当前白银顺序：Mercedes-Benz Mercedes-AMG GT Black Series → Renault R.S. 01 → Lamborghini Miura Concept → Lamborghini Huracan STO → TVR Sagaris；随后尝试青铜 Kimera EVO37 → Hyundai IONIQ 5 N → Praga R1。青铜 Volkswagen Electric R 排在 EVO37 后，但当前缺列表模板，暂跳过推荐定位，由倒序详情遍历处理。素材不足不阻挡其他候选。旧 Excel 推荐不再用于此循环。

运行配置为 `first_available_in_order`，每局读取首页评级徽章，白金可使用白金及以下车辆，黄金和白银同样向下兼容。每辆推荐车先定位下一段位起点，再向右拖动列表以反向搜索：白金从翡翠起点反查，黄金从白金起点反查，白银从黄金起点反查，青铜从白银起点反查。最多 24 次；仍未找到则跳到本段位起点，正向搜索最多 24 次，两端覆盖后才换下一候选。命中车名后点击左侧车身，避开整个图纸区域；贴左边且车身不完整的卡片先不点击。误入图纸获取页会专用关闭并重选同一候选，最多恢复两次。缺油、未拥有或段位不可用继续下一候选。名单耗尽后从当前段位的下一段位起点进入倒序详情兜底；青铜首车不可用或达到左切上限就停止。服务器恢复也使用相同搜索流程与独立计数。

找到可开始车辆后确认 TouchDrive 开启，若点击开始后仍留在详情页最多重试至总共 3 次；等待匹配和加载最多 180 秒。识别局内 HUD 后执行双击氮气组合：两次点击间隔 750 毫秒，第二次点击后等待 6000 毫秒再检查画面；最多 42 组，保留约五分钟局内操作上限。每组之间优先检查结算，组内不重新识别。成绩继续 → 奖励继续 → 等待错失机会 → 返回系列赛。奖励页点击后若仍停留原页，最多重试至总共 3 次；出现错失机会按钮则优先点它，不继续点奖励。出现“赛季完赛奖励”的升级页，点击右下角继续 (1132,653)，接回奖励/广告跳过/返回系列赛。只有结算返回系列赛后才记本局完成并进入下一局。降级提示使用 `多人游戏_段位_降级_到白银.png`，节点为 `多人段位_降级确定`，先确认再进入下一局并重新读取段位，不再暂停人工更新；未覆盖页面超时后停止。

3 局与 20 局分别使用每局独立命名的节点组，隔离 max_hit 计数，不依赖 Agent 或外部 Maa SDK。无需手动重置节点计数。20 局版本只有局数上限，没有真实的 60 分钟计时器。

广告关闭、连接重试和车库领取为可选分支，处理后重新判断页面接续，不统一按房子回主页。每局连接重试最多 10 次。暂不包含通用游戏重启、任意陌生弹窗或动态段位识别。未知状态按节点超时进入明确停止节点，检查 Maa 日志中的最后节点及标准截图即可定位。

多人服务器错误使用标题与 × 双重识别，关闭后等待 2 秒，再确认回到选车列表。重新开启仅拥有，按推荐顺序选车；推荐车不可用时接倒序兜底，确认有油、可开始及 TouchDrive 开启后重新开赛。每局最多恢复三次，每次使用独立的选车、滑动与开始计数，避免原节点的 max_hit 阻止恢复。服务器错误不会累计完成一局，也不会返回主页。持续失败或未回到可识别选车列表时停止。

循环是新接入的设备试跑版本，不能将截图检查通过当作长时设备运行通过。初次观察是否正确选车、只点一次开始、加载后触发氮气、结算返回后进入第02局。异常出现后使用 debug/maafw.log 和对应失败截图继续修复；不需要人为耗光全部车辆。

```powershell
python -X utf8 tools/prepare_dynamic_multiplayer_loop.py
python -X utf8 tools/validate_schema.py --schema-dir deps/tools
```

结算支持 `名人堂奖励.png`：匹配名人堂标题与右下继续，点击 (1154,660) 后继续检查升降级提示及系列赛首页。奖励数额不参与匹配；名人堂页不计本局完成，确认回到系列赛后才计数。广告关闭位于所有页面识别动作之前，随后处理服务器错误、图纸恢复及结算。

结算后若出现通行证升级奖励弹窗，同时识别“级别”“现已解锁”“领取”与右上角 × 并关闭。等级数字不参与匹配。关闭后继续等待结算返回系列赛的确认，不能从通用页面调度直接开始下一局；弹窗本身不计为完成一局。

运行时推荐车若在列表中显示零燃油，会直接转向下一优先车辆的正向搜索，不再为了这辆缺油车先扫完整段位再从终点反查。服务器错误弹窗点击 × 后会再次确认弹窗是否消失；仍在时有限次数重试关闭，回到选车列表后才启动独立的恢复选车分支。
