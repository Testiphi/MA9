# 指定车辆定位测试

这个任务只测试多人选车列表的定位。它不会点击右下角“开始”，找到目标后停在车辆详情页。起点模式从目标车辆段位的第一个列表页面开始，手势向左滑、沿车辆顺序向右搜索；终点模式先跳到下一个段位起点，再用手势向右滑回目标段位末尾，沿车辆顺序向左搜索。**选车列表不循环：青铜是左边界，传奇没有下一段位锚点。**因此选择“传奇终点”时会明确改从传奇起点向左滑搜索；详情页左箭头的循环只属于详情页。每个方向最多检查 50 页，识别到段位边界或列表停滞会停止。

运行前先在 MuMu 中进入**多人选车列表**。任务会在需要时开启“仅拥有”。在排序窗口选择一辆车，点击“从起点定位测试”或“从终点定位测试”；默认重复 3 次，每次都从所选边界重新开始，最后一次停在详情页。然后在 MA9 主程序运行 **指定车辆定位测试（从起点或终点，停在详情，不开赛）**。

也可以从项目根目录设置测试目标：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/set_vehicle_search_test.py "Porsche Panamera Turbo S" --from start --repeats 3
```

将 `start` 改成 `end` 可测试倒序路径。测试目标必须是车库中已确认拥有的车辆。运行后查看 `debug/vehicle_location_test.json`：每次尝试记录页数、耗时、点击坐标及结果；`status: found` 表示重复尝试都到达详情页。如果失败，任务停下而不会继续开赛。修复后应对同一辆车分别测试起点和终点，并检查最终详情页确实是目标车。

实机反查黄金 Panamera 时，列表中 Praga Bohema 的品牌曾被 OCR 读成 `Proqo`，使整页提前报 `ocr_incomplete`。现在只有在同段位中车型后缀唯一时才允许用车型名补救品牌误读，并在页面短暂未稳定时最多重读 5 次。仍读不出的卡片会把位置写进报告的 `unreadable_cards`，不会猜测并点击。

本模块的离线测试覆盖起点/终点路由和重复返回；通用详情页识别模板在现有 40 张详情截图中命中 40 张，在选车截图中无误命中。模拟器未连接时无法验证真实滑动与点击，首次设备测试仍需观察边界跳转和详情页车辆名称。
