规则已确认：五张小图算一次进攻挑战，至少赢三张才算整组获胜；点进进攻页面即扣一张票。主动退出或中断会留下“未完成”，结算后点击“继续”可获得失败时的一个巴掌。巴掌动画中的 `+5` 是临时字样，应以左侧稳定的 `n/22` 为准。比赛已经开始后，正常流程是在每场结算页点“继续”进入下一场，不要求返回主页重新定位；目前不专门处理跑完一场后意外退出的恢复。

防守选车当前使用自适应多帧稳定采样：稳定页面连续两次读数一致即可继续，滚动车名或不完整页面保留更多读取机会；列表必须连续两次滑动均未移动才判定末端。首次完整扫描会记录每辆车的近似页码，后续逐格选车先快速滑到目标附近再精确核对，定位失败则从等级开头完整重扫。误点相邻车辆详情会返回列表并重新核对车辆名称、性能分和可读的星级。所选等级不足五辆时按 `R→S→A→B→C→D` 向下补足并保持车辆互斥。扫描完成与五车配置完成是两个独立状态，前者不能让图形化任务报告成功。

详情页的固定“选择”按钮不以 OCR 全文作为点击条件：在右下固定区域用资源内模板识别按钮文字，并同时验证按钮仍是明亮绿色。这样遮罩弹窗中仍可匹配到的暗按钮不会被点击；已占用提示、车型、性能分和星级检查仍在按钮检查之前。详情页及按钮最多各随同一轮详情读取等待 8 次；车型已核对但按钮始终不可用时返回 `select_unavailable`，不会盲点。列表页性能分若已从整页 OCR 获得唯一、置信度足够的四位当前分，则省去一次局部补读；三位、残缺或多读数仍保留既有补读和详情复核路径。

列表页卡片左边界必须由**带字母**的名称条目锚定。左侧被裁切的那一列，其最后一项统计数字与当前行的车型名同高，而这类纯数字文本同样满足名称候选的字符要求，一旦并入名称组就会把左边界整体左移，性能分 ROI 随之覆盖到邻列的统计数字。2026-09-22 23:18:23.444 的冻结帧正是该形态：IONIQ 5 N 的左边界被拉到 34（实际 184），退化路径把邻列统计 `@71.54` 拼成 7154，随后降序护栏（正确地）拒绝整个读数链并终止本轮，`assigned` 为空且未开始比赛。现在几何只由带字母的条目决定（整组都没有字母时回退到原行为），邻列纯数字不再能移动卡片，点击落点与被判读的徽标重新一致；同一帧复读得到 IONIQ 5 N 2559、Praga R1 2559/2624、Infiniti Project Black S 2371、Peugeot SR1 2307。该修正同时消除了 Camaro LT 3084、Z4 LCI E89 2841、Challenger SRT8 2912 这类同源假读数，并使跨帧读数趋于唯一。

DS E-Tense 的 976 不属于上述缺陷：同一帧的另一次读数是 1976，属真实的千位截断，由列表降序还原机制处理，不得自行改数。冻结那次运行使用的是安装目录中的旧构建（`duel_vehicle_screen` 为 b9d0ade 世代），不是本轮测试包；但上述配对缺陷在 0850f33 中同样可按记录 OCR 复现，因此修复落在本席源码而非版本差异。

后续按以下顺序推进：

1. **防守实机回归（中）**：从资格赛失败页和空防守页各跑一次 D 级，验证科迈罗等滚动车名、连续滑动和五格最终状态。
2. **其他等级交界实机验证（中）**：优先测试车少的 R 级，确认 R/S 混合页的边界和向下补车；再抽测一个中间等级。
3. **车库清单持久化（中）**：把已识别的车辆 ID、等级、星级和当前性能分保存为账号车库快照，为进攻规划提供输入。
4. **MutualExclusionAllocator 数据适配（高）**：现有 Python `plan_attack` 已实现同类回溯与帕累托互斥算法；还需把五张实机地图、账号车库、星级与可用状态转换为候选组，并把方案逐格交给当前的车辆定位器。
5. **进攻闭环（高）**：读取三档对手详情、选择对手、配置五车、依次比赛、结算至少三胜及稳定的 `n/22` 巴掌数。票券只在进入进攻页面后记录。

另行继续对手信息和五图结果的 OCR 提取、胜负与巴掌计数判定，并在保存截图上回归。实机恢复后仍需验证点击目标、票券扣除时机，以及重登后尚未开赛的临时配车是否保留；不能根据本地日志推断当前游戏状态。
