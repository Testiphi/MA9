# 多人加载、局内与结算样例

提供以下独立任务：

- `多人结算（继续，错失机会，返回系列赛）`：从成绩、奖励或广告提示任一阶段开始；成绩继续 → 奖励继续 → 等待右下错失机会出现并点击 → 确认系列赛介绍页。已有返回页面时不点击。奖励继续的后继只有错失机会与返回判断，不会在广告提示尚未出现跳过按钮时重复点击继续。未出现广告直接返回时也可结束。
- `识别赛道（神山垭口，坠落，加载页）`：仅识别加载页左上大地图和小地图，终点 `赛道识别_神山垭口_坠落`。不裁车型、玩家或排名。
- `识别多人局内HUD（不操作）`：仅确认暂停图标与 TouchDrive 标识，不点击、不读百分比。TouchDrive 背景透明，标识模板阈值为 0.8，并以暂停图标的 0.9 条件共同限制局内页面。
- `多人局内兜底（每5秒氮气，结算后返回）`：确认局内 HUD 后立即点击右侧氮气键 `(1080,560)`，等待 5000ms，再重新读取画面决定下一步。持续在局内时约每 5 秒点击一次，不限制点击次数。结算页面优先于氮气判断，出现成绩、奖励或降级页面后进入现有结算流程，返回系列赛时结束。可在加载页启动，最多等待 180 秒；局内 HUD 消失且结算未出现时最多等待 60 秒，不继续盲点。尚未根据百分比或赛道决定操作。

结算不会点击广告“免费”按钮。错失机会按钮识别到了才执行，无需假设固定一两秒必定出现；允许等候最多 60 秒。结算后只停在系列赛介绍页，不继续选车或开赛。返回判断使用底部排行榜、里程碑、奖励三项固定按钮，以及里程碑按钮区域的白色像素数量，不依赖标题着色、车模、段位、评级分或开始按钮。若返回期间出现“你已降级!”弹窗，优先确认标题和确定按钮，点击 (634,527) 后再检查返回。白色亮度条件防止暗色遮罩下的页面被当作已完成。其他系列赛返回页仍需验证。

用户提供的神山垭口/坠落局内进度为 18、50、67、78、91。配置位于 `data/sources/multiplayer_tracks.json`：登记赛道名称、1 圈、左上进度 ROI `[188,54,62,33]`、局内原图列表；进度读取状态 `ocr_pending`，操作列表为空。固定进度截图用于以后验证 OCR，不能代替任意百分比读取；尚未安装 OCR 模型，也未实现局内百分比调度或赛道动作。

刷新 Maa Pipeline Support，从成绩页运行结算任务，确认点击两次继续后能等到错失机会，再返回并结束在 `多人结算_已返回系列赛`。可从奖励页、广告提示页分别测试。加载和 HUD 识别任务只在对应页面运行。氮气兜底任务可在加载页或局内运行，需要设备确认氮气触发及结算衔接；当前黄金选车任务仍停在准备界面，可手动开始比赛后运行兜底任务。

生成：`python -X utf8 tools/prepare_race_screens.py`；配置校验：`python -X utf8 tools/validate_schema.py --schema-dir deps/tools`。63 张截图、七类页面共 441 项正反例检查通过；遮掉广告跳过按钮时，不会识别成可跳过或再次奖励继续。真实失败返回页已保存为 `多人游戏_结算_返回后.png`；遮掉其整个车模、段位信息与开始按钮，仍可确认返回，降级遮罩页则不能当作返回完成。新增返回与降级分支仍需设备验证。

名人堂奖励页使用 `名人堂奖励.png`，节点 `多人结算_名人堂奖励继续` 联合匹配标题和继续按钮，点击右下 (1154,660) 后等待后续提示或系列赛。它是可选分支，不要求每局出现。独立结算与多人循环均优先关闭广告。
