# 对决赛区与五图候选只读流程

这个流程分两次运行。用户先停在多人游戏首页；第一步读取右侧“对决”卡片下方完整的“赛区 V”或“赛区 IV”，并核对左侧“世界系列赛”卡片、右卡标题和底栏已选中的多人游戏标签。用户随后手动进入已有的五车阵容页面；第二步重新读取当前五张地图，只展示第一步所读赛区的自动档候选。程序在两步中都不点击、不配置车辆、不开始比赛。

主页读取使用 `selection_runtime.frame_of` 规范化后的 1280×720 图像。一次 OCR 取同帧的 `(180, 350, 920, 360)` 区域。标题和赛区行必须有至少 0.85 的置信度及相应卡片内的完整坐标；赛区文本仅在 Unicode NFKC 规范化、去空白后接受 `赛区V` 或 `赛区IV`。冲突、缺字、`VI`、`V1` 或错误页面都会拒绝。连续两张独立截图得到同一赛区才确认。OCR 的 30 秒期限只限制开始新截图，不能中断已经在途的识别。

第一步在隔离运行根的 `debug/` 下保存带 UUID 的 JSON 和可读 Markdown 报告。确认成功时，还写入固定的 `debug/duel-zone-session.json` 会话指针，其中包含账号标签、运行根、赛区、UTC 创建时间和原报告 SHA-256。新的第一步会先废弃旧指针，即使这次识别失败也不会沿用旧赛区。

第二步只接受同一运行根和账号标签中尚未消费、创建后 600 秒内的指针。它重新核对原报告内容与 SHA-256，先将会话持久标记为已消费，再读取新的五图和候选表。五图必须稳定核验成功；采集后还会再次检查时限。失败会保留明确失败报告，已消费会话不能重试；要重试需从首页重新运行第一步。成功报告只列出选定赛区的五个地图槽候选，保留地图报告、赛区报告、会话 ID、候选表和车辆目录的关联哈希。候选仅供预览，没有车库拥有状态或可用状态证明。

账号标签来自隔离根的用户确认配置，并不是画面中的账号视觉认证。两步之间请保持同一个测试账号和运行根。这个短期会话只约束只读预览，不是车辆选择或开赛的执行授权。
